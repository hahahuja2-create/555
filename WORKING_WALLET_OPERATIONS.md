# Working wallet operations

Automatic operation is opt-in. With both automatic flags disabled, existing deposit addresses, the configured treasury and manual withdrawal behavior remain unchanged. The deposit branch must not be replaced: the production database records its fingerprint and user address indices.

The working wallet receives automatically collected USDT and signs automatic customer withdrawals. The personal owner address is a separate fixed destination; no transfer to it is created by a timer. An administrator must enter the amount and confirm their account password in **Admin → Working wallet**. Signed bytes are stored before broadcast and a transfer becomes confirmed only after the expected solidified USDT event is checked. Requests are serialized against unresolved customer payouts. Insufficient funds or resources leave a request pending. A request that has already been signed cannot be cancelled merely because it expired or its network outcome is unknown.

The hosted process has access to both the deposit-branch mnemonic and the working wallet private key, so a compromise of that hosting environment can expose both the deposit addresses and the working wallet. Keep the personal treasury key off the host. Do not put any secret in Git, a browser, logs or chat. Keep separately protected recovery copies for both wallets and rehearse recovery before funding. This is not a substitute for an independent security review.

The existing fuel address pays TRX for collection transactions. With the current conservative 20 TRX Energy cap, a deposit address is funded up to 21 TRX and the fuel wallet needs 23 TRX available for that funding operation. Payout preparation requires the working wallet to hold at least 21 TRX. These amounts are reserves, not actual transaction fees. The current implementation does not rent or delegate Energy; staking or rental requires further implementation and separate verification. Wallet balances and available resources must be monitored.

The treasury change requires a fresh deposit-branch ownership proof bound to the working wallet, while keeping the same xpub, derived addresses, database and address indices. Before cutover, stop the old local collection service, reconcile all existing collection and withdrawal jobs, and check the new signed public configuration and both recovery copies. Startup fails closed if a previous-treasury collection or legacy withdrawal is unresolved. Never automatically retry a signed transaction with new bytes solely because it expired or the network response was lost.

`npm run test:automation` runs isolated fixtures. `TASKMALL_MYSQL_INTEGRATION=1` enables MySQL tests in a separately created empty test schema; it never imports production data. These tests do not replace a small controlled Mainnet rehearsal. The working wallet needs real USDT liquidity before it can pay withdrawals; displayed account balances are not proof of on-chain reserves.
